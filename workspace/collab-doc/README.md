# 多人协作文档（离线可编辑 · CRDT 合并 · 锚定评论 · 修订时间线 · 空间成员治理 · 有界流水压缩）

零依赖实现（仅 Node.js 内置模块 + 原生 Web API），前端与服务器同容器运行。

## 有界流水压缩与基线代次（v3）

长期活跃空间的操作流水会持续增长。v3 在不改变任何投影视图的前提下压缩回收：

- **基线代次（generation）**：压缩以 cutoff 时刻的存活状态构建新基线代次（g 单调递增），把存活字符线性重排为规范 id，样式标记按偏移重挂，批注逐锚点换算；**正文投影、样式标记、批注、成员关系、授权纪元、治理账本次序在压缩前后逐项相等**。
- **回收对象**：cutoff 之前的操作流水、修订全量快照、字符墓碑。磁盘流水（尾部 ops + 快照）受 `LOG_CAP_BYTES` 上界约束，超阈自动再压缩；前向 id 映射直接由基线字符的来源 id 派生，**不保留隐藏的全量副本**。
- **原子切换、抗宕机**：新代次先写 `.tmp` 并 `fsync`，再 `rename` 为权威文件。发布前任一时刻宕机重启仍是完整旧代，发布后宕机是完整新代；重试压缩不破坏权威态。两阶段（stage/publish）允许「制作基线期间继续在线写入」，切换点以最新状态重建基线，边界两侧变动不丢不重。
- **保留基线点与回退**：保留最近 `RETAIN_BASELINES`（默认 3）个基线点。回退到仍保留的基线点会产生**新代次与一条演进记录**；请求已被回收的基线点返回明确错误 `baseline-unavailable` 且不增加演进记录。

## 快照迁移与基线换算（落后于保留窗口的镜像端）

- 镜像端 `hello` 携带 `gen/lastSeq`；落后时收到 `welcome{needMigration}`，随后接收 `genSwitch → baselineChunk*（可重复/乱序、按片幂等拼装）→ baselineEnd`（基线 + 尾部流水 + 治理态）。
- 积压的插入/擦除/样式/批注批次以 `migrate{migId,fromGen,ops}` 提交，服务器用跨代 id 前向链**确定性换算**：
  - 仍存在前向/后继映射的引用**保留改动意图**（插入位置沿 RGA 后继穿链）；
  - 指向已回收墓碑的**具体锚点**（删除目标、样式边界、批注锚点）无法映射时产出**说明明确的冲突草稿**，绝不悄悄挂到另一段字句；
  - 本人在新基线显式选定新位置并**核准（approve）后才再次生效**，核准按 `approveId` 幂等、只生效一次。
- **重连裁决仍以当前成员纪元 epoch 为准**：降权/移除主体的陈旧迁移批次整批拒绝、零发布；完整载荷（ops 原文）可读、可复制，落盘并**跨下一轮压缩与重启保留**。
- 基线请求、迁移分片、换算批次（`migId`）、重复重连、进程重启全部幂等；重复/乱序分片不重复正文投影、基线点、冲突项或账本事件。

## 可观测（主理人无需改存储文件即可排查）

侧栏「代次与有界流水」展示：当前代次、保留序号区间、磁盘流水占用与配置上界、各镜像端的水位回执/租约（gen、lastSeq、是否当前代）、保留基线点（可一键回退）、最近压缩失败原因。owner 可手动「立即压缩并发布新代次」。相关环境变量：`LOG_CAP_BYTES`（默认 90000）、`RETAIN_BASELINES`（默认 3）、`SHARD_CHARS`（默认 300）。

## 空间成员治理（owner / editor / commenter / viewer）

| 角色 | 正文与样式（ins/del/mark） | 批注（com：创建/解决/重新挂接） | 邀请 / 改角色 / 移除 | 回滚检查点 |
|---|---|---|---|---|
| owner 所有者 | ✅ | ✅ | ✅ | ✅ |
| editor 编辑 | ✅ | ✅ | ❌ | ❌ |
| commenter 评论者 | ❌ | ✅ | ❌ | ❌ |
| viewer 只读（含未邀请/被移除者） | ❌ | ❌ | ❌ | ❌ |

规则在 `shared/authz.js` 中唯一实现，浏览器（按角色禁用命令/编辑器）与服务器（最终授权方）共用。

- **审计账本与统一总序**：每次成员变更（空间初始化/升级、邀请、角色变更、移除）写一条审计条目；审计条目与内容修订**共用同一条全局单调 `seq`**，并带「授权纪元 `epoch`」。侧栏「审计账本」把两者按 seq 合并展示，成员变更与修订的相对先后对所有人明确一致。
- **原子批次授权（断连降权冲突为一等公民）**：参与者可在断连时排队操作；若重连前被降权或移除，服务器按当前 epoch 对**整个批次**授权——批次中任一操作越权则**整批拒绝、零发布、不占 seq**，并持久化隔离引用。浏览器把被拒操作完整保留在可读、可复制的**隔离草稿**中，解释拒绝原因与相关角色变更（epoch/seq），**必须显式点击重新提交**，且仅在权限恢复后可提交。
- **三级幂等**：成员变更用 `reqId`、操作批次用 `batchId`、单条操作用 `opId` 去重，均落盘。重试、重复投递、进程重启都不会重复一次成员变更、内容生效或审计条目。
- **旧版空间升级**：无成员元数据的 v1 数据文件在**首次打开**时初始化**恰好一个 owner**（Node 单线程 + 同步落盘，并发首开也只有一个），既有 `ops/revs`（内容、批注、修订历史）原样保留，仅追加一条 `space/upgrade` 审计。
- 最后一个所有者不允许被降权或移除。

## 功能与需求对应

| 需求 | 实现 |
|---|---|
| 断网后仍能编辑 | 所有编辑先应用到本地 CRDT 并写入 `localStorage`；断网期间操作按**批次**进入待同步队列，页面刷新/重开也不丢 |
| 恢复连接后合并插入/删除/格式 | 文本用 **RGA** 序列 CRDT（删除=墓碑，插入按全局唯一 id 定序），格式用 **LWW 标记**，三者都是可交换、幂等的操作，重连后双向补发即收敛 |
| 较晚同步不覆盖他人已确认内容 | CRDT 的数学性质：操作可交换且幂等，迟到的操作只会"合并进来"，不存在覆盖语义 |
| 评论锚定到文字范围 | 锚点指向**字符 id** 而非偏移量（相对位置），并发编辑后仍落在正确文字上 |
| 文字被拆分/删除 → 可解释悬空 | 评论记录创建时的原文 `quote`，实时对比当前覆盖文字，区分 5 种状态：`已锚定` / `已拆分` / `部分悬空` / `悬空` / `已变更` |
| 允许重新挂接 | 悬空评论点"重新挂接"，在文档中选中新范围即可（需评论者或更高角色），作为评论的 LWW 更新同步给所有人 |
| 一致的修订时间线 | 服务器为每个内容操作分配全局递增 `seq`，每个操作批次形成一个修订（含快照），所有客户端看到同一时间线 |
| 恢复历史版本（仅 owner） | 恢复 = 服务器生成一批普通的删除/插入/格式操作，**作为新修订**进入操作流；非所有者请求被拒绝且不产生修订 |
| 容器化一起运行 | 单一 `Dockerfile`（服务器直接托管前端静态文件），另附 `docker-compose.yml` |

## 运行

```bash
# 本地
npm start          # http://localhost:8080  （PORT 环境变量可改端口）

# 测试（20 项集成测试：角色矩阵 / 断连降权隔离 / 重提幂等 / 竞争总序 /
# 非所有者回滚拒绝 / 重启持久化 / 旧版并发首开升级 / CRDT 协作回归）
npm test

# Docker
docker build -t collab-doc .
docker run -p 8080:8080 -v collab-data:/app/data collab-doc
# 或
docker compose up --build
```

打开 `http://localhost:8080`（可加 `?doc=xxx` 使用不同文档），多开几个窗口即多人协作；开 DevTools 离线模式可验证断网编辑与重连合并。

### 同步与治理协议

- 客户端连接时发送 `hello{clientId,name,doc,lastSeq}`，服务器回
  `welcome{ops,revs,ledger,members,epoch,role,member,initEntry?}`；首开者成为 owner，旧版空间首开追加 `upgrade` 审计。
- 内容批次：`ops{batchId,ops[]}`；服务器按当前 epoch 对全批原子授权：
  - 接受 → 连续 `seq`、形成修订、广播 `ops{batchId,applied,rev,epoch}`；
  - 拒绝 → 仅回发起者 `batchAck{status:'rejected',epoch,atSeq,role,need,reason,kinds}`，整批不发布；
  - `batchId` 已处理 → 原样回放首次结论（重复投递不二次生效）。
- 成员变更（仅 owner）：`member{reqId,act:invite|role|remove,target,role}`，成功后 epoch+1、
  审计条目占用下一个 seq、广播 `members{epoch,members,entry}`；相同 `reqId` 重放为幂等 no-op。
- 回滚（仅 owner）：`restore{rev}`；越权回 `error{code:'forbidden-rollback'}`，不产生任何 seq/修订。
- 客户端本地持久化 `{v:2,lastSeq,allOps,pendingBatches,quarantine,revs,ledger,members,epoch,...}`；
  批次被拒后从「已确认操作 + 其余待发批次」重建本地 CRDT，被拒批次仅存在于隔离草稿，等待显式重提。

### 关键设计取舍

- **不用任何 npm 依赖**：WebSocket 协议、CRDT、治理、前端均为手写，镜像构建无需联网安装依赖，`node:20-alpine` 即可运行。
- **统一 seq、分轨存储**：内容操作与成员审计共用同一全局 seq 计数器（总序明确），但分别存于 `ops/revs` 与 `ledger`（语义独立）。
- **授权纪元 epoch**：成员变更使 epoch 单调递增；拒绝结果与批次记录都带 epoch，便于跨重启解释"按哪个版本的权限做的决定"。
- **成员变更/隔离引用同步落盘**，普通内容编辑走 2s 批量落盘（opId 幂等保证重启后补发不重复）。
- **RGA 文本**：实现简单、删除不丢信息（墓碑）；已知局限是极端并发下可能出现字符交织（interleaving），对协作文档场景可接受。
- **格式 = 范围标记的并集**：同一属性键在覆盖同一区段的多个标记间按 `(ts, author)` 取最后写者，支持"加粗→取消加粗"。
- **批注/格式更新按 id LWW**：同一批注被两人同时修改时，全系统收敛到同一结果。
- **恢复快照只含文本+格式**：批注不随恢复回滚——被恢复操作删掉锚定文字的批注会按规则进入可解释的悬空状态，可重新挂接。

## 已知限制（演示级）

- 身份为自报 `clientId`（localStorage 持久），无密码/令牌鉴权；任何知道 ID 的连接都能以该身份加入，
  生产环境应在 WebSocket 握手层接入真实认证并把用户主体传入成员表；
- 单进程内存 + JSON 全量落盘，未做水平扩展；审计账本/修订快照有数量上限；
- 修订快照为全量文本，适合中小文档；
- 编辑器基于 contenteditable + 前后缀 diff，IME 组合输入已做基本处理，复杂嵌套富文本（表格、图片）未支持。
